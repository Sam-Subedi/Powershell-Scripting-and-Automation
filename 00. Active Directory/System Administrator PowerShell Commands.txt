POWERSHELL SYSTEM ADMINISTRATOR COMMAND REFERENCE
Environment:
Domain: abc.local
Main OU: Employee
Sub-OUs: Sales, IT, HR, Marketing
Example DC: DC01.abc.local

IMPORTANT:
- Test administrative scripts in a lab before production deployment.
- Use least privilege. Do not add accounts to privileged groups such as Domain Admins or Schema Admins unless the role genuinely requires it and your organization's change/approval process permits it.
- Commands that change firewall, RDP, remoting, services, users, groups, registry, or permissions can affect production systems.
- Run commands in an elevated PowerShell session when required.
- The ActiveDirectory module is normally available on a DC or RSAT-installed admin workstation.

2. ACTIVE DIRECTORY - USERS
======================================================================

Find a user:
Get-ADUser -Identity sam.smith

Detailed user information:
Get-ADUser sam.smith -Properties *

List all users:
Get-ADUser -Filter *

List enabled users:
Get-ADUser -Filter 'Enabled -eq $true'

List disabled users:
Get-ADUser -Filter 'Enabled -eq $false'

Find users by department:
Get-ADUser -Filter 'Department -eq "Sales"'

Find users in Sales OU:
Get-ADUser -SearchBase "OU=Sales,OU=Employee,DC=abc,DC=local" -Filter *

Find users in IT OU:
Get-ADUser -SearchBase "OU=IT,OU=Employee,DC=abc,DC=local" -Filter *

Find users in HR OU:
Get-ADUser -SearchBase "OU=HR,OU=Employee,DC=abc,DC=local" -Filter *

Find users in Marketing OU:
Get-ADUser -SearchBase "OU=Marketing,OU=Employee,DC=abc,DC=local" -Filter *

Create a user directly in Sales OU:
New-ADUser -Name "Sam Smith" `
    -GivenName "Sam" `
    -Surname "Smith" `
    -SamAccountName "sam.smith" `
    -UserPrincipalName "sam.smith@abc.local" `
    -Path "OU=Sales,OU=Employee,DC=abc,DC=local" `
    -AccountPassword (Read-Host "Temporary password" -AsSecureString) `
    -Enabled $true `
    -ChangePasswordAtLogon $true

Create user in IT:
New-ADUser -Name "Sam Smith" -GivenName "Sam" -Surname "Smith" `
    -SamAccountName "sam.smith" -UserPrincipalName "sam.smith@abc.local" `
    -Path "OU=IT,OU=Employee,DC=abc,DC=local" `
    -AccountPassword (Read-Host "Temporary password" -AsSecureString) `
    -Enabled $true -ChangePasswordAtLogon $true

Modify department:
Set-ADUser sam.smith -Department "Sales"

Modify title:
Set-ADUser sam.smith -Title "Sales Representative"

Modify phone:
Set-ADUser sam.smith -OfficePhone "0400000000"

Disable account:
Disable-ADAccount -Identity sam.smith

Enable account:
Enable-ADAccount -Identity sam.smith

Unlock account:
Unlock-ADAccount -Identity sam.smith

Reset password:
Set-ADAccountPassword -Identity sam.smith -Reset `
    -NewPassword (Read-Host "New password" -AsSecureString)

Force password change at next logon:
Set-ADUser sam.smith -ChangePasswordAtLogon $true

Move user from Sales to IT:
Move-ADObject `
    -Identity "CN=Sam Smith,OU=Sales,OU=Employee,DC=abc,DC=local" `
    -TargetPath "OU=IT,OU=Employee,DC=abc,DC=local"

Delete user:
Remove-ADUser -Identity sam.smith

9. REMOTE DESKTOP (RDP)
======================================================================

IMPORTANT:
Enabling RDP changes remote access exposure. In production, combine RDP
with firewall restrictions, network controls, MFA/NLA where applicable,
and organizational policy.

Check RDP registry setting:
Get-ItemPropertyValue `
    "HKLM:\SYSTEM\CurrentControlSet\Control\Terminal Server" `
    -Name fDenyTSConnections

Enable RDP:
Set-ItemProperty `
    "HKLM:\SYSTEM\CurrentControlSet\Control\Terminal Server" `
    -Name fDenyTSConnections -Value 0

Enable Remote Desktop firewall rules:
Enable-NetFirewallRule -DisplayGroup "Remote Desktop"

Disable RDP:
Set-ItemProperty `
    "HKLM:\SYSTEM\CurrentControlSet\Control\Terminal Server" `
    -Name fDenyTSConnections -Value 1

Disable Remote Desktop firewall rules:
Disable-NetFirewallRule -DisplayGroup "Remote Desktop"

Enable Network Level Authentication:
Set-ItemProperty `
    "HKLM:\SYSTEM\CurrentControlSet\Control\Terminal Server\WinStations\RDP-Tcp" `
    -Name UserAuthentication -Value 1

List members of Remote Desktop Users:
Get-LocalGroupMember -Group "Remote Desktop Users"

Add local user to Remote Desktop Users:
Add-LocalGroupMember -Group "Remote Desktop Users" -Member "localadmin"

Add domain user to Remote Desktop Users:
Add-LocalGroupMember -Group "Remote Desktop Users" -Member "ABC\sam.smith"

Remove user from Remote Desktop Users:
Remove-LocalGroupMember -Group "Remote Desktop Users" -Member "ABC\sam.smith"

29. MULTIPLE COMPUTER HEALTH CHECK
======================================================================

$Computers = Get-ADComputer -Filter * |
    Select-Object -ExpandProperty Name

Invoke-Command -ComputerName $Computers -ScriptBlock {

    $OS = Get-CimInstance Win32_OperatingSystem
    $Disk = Get-CimInstance Win32_LogicalDisk -Filter "DeviceID='C:'"

    [PSCustomObject]@{
        ComputerName = $env:COMPUTERNAME
        OS = $OS.Caption
        LastBoot = $OS.LastBootUpTime
        DiskFreeGB = [math]::Round($Disk.FreeSpace / 1GB,2)
        MemoryGB = [math]::Round($OS.TotalVisibleMemorySize / 1MB,2)
    }

} | Export-Csv "C:\Reports\ComputerHealth.csv" -NoTypeInformation

34. PRODUCTION SCRIPTING PATTERN
======================================================================

A practical production script should normally consider:

1. Least privilege
2. Input validation
3. Error handling
4. Logging
5. Clear output/reporting
6. Testing before deployment
7. Change management
8. Maintenance window when required
9. Backup/recovery plan for destructive changes
10. Idempotency where possible
11. Secure credential handling
12. Scope limitation
13. Confirmation for destructive actions
14. Appropriate permissions
15. Auditability

Useful pattern:

$Computers = @("PC01","PC02","PC03")
$LogFile = "C:\Logs\Admin.log"

New-Item -Path "C:\Logs" -ItemType Directory -Force | Out-Null

foreach ($Computer in $Computers) {

    try {

        "[$(Get-Date)] Starting $Computer" |
            Out-File $LogFile -Append

        Invoke-Command -ComputerName $Computer -ScriptBlock {
            Get-ComputerInfo |
                Select-Object CsName,WindowsProductName,WindowsVersion
        } -ErrorAction Stop

        "[$(Get-Date)] Completed $Computer" |
            Out-File $LogFile -Append

    }
    catch {

        "[$(Get-Date)] FAILED $Computer : $($_.Exception.Message)" |
            Out-File $LogFile -Append
    }
}
